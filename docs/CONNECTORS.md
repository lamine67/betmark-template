# Как подключить свою контору

Коннектор - модуль, который обращается к **одной** букмекерской конторе и приводит её данные к формату Betmark.
В этом репозитории настоящих коннекторов нет: только демо (`lib/collectors/demo.ts`) и заглушки с готовыми сигнатурами.

> Соблюдайте условия сайтов, с которыми работаете. Не обходите капчи, проверки на бота и другую защиту, не создавайте
> лишнюю нагрузку (разумные интервалы опроса, один запрос на все матчи вместо запроса на каждый). Если сайт закрылся
> проверкой, это повод остановиться, а не искать обход.

## 1. Прематч: функция, возвращающая матчи

Контракт описан в `lib/collectors/types.ts`:

```ts
export interface NormalizedMatch {
  externalId: string;          // стабильный id матча у конторы
  sourceUrl?: string | null;   // ссылка на карточку матча (необязательно)
  homeTeam: string;
  awayTeam: string;
  kickoffAt: Date;             // момент начала, всегда в UTC-совместимом Date
  leagueName: string;          // «Страна. Лига»: по этому формату склеиваются лиги разных контор
  odds: { outcome: "1" | "X" | "2"; price: number }[];   // рынок 1X2; для хоккея и тенниса исходы без X
}
```

Пример коннектора - `collectDemoFootball()` в `lib/collectors/demo.ts`.

Правила, которые важны для качества данных:

- `price` строго больше 1; пустые и «закрытые» исходы не отдавайте вообще.
- Названия команд передавайте как есть: приведение имён и склейку одного матча у разных контор делает `lib/matching.ts`.
- Перепутанный порядок «хозяева-гости» не исправляйте руками: определение ориентации есть в `lib/orientation.ts`.
- Время начала берите в UTC или с явным часовым поясом. Ошибка на час даёт «двойное расписание» и несклеенные дубли.

## 2. Файл запуска синхронизации

Скопируйте `sync-booka.ts` в `sync-<slug>.ts`:

```ts
import { runFootballOrHockeySync } from "./lib/syncRunner";
import { fetchMyBookMatches } from "./lib/collectors/mybook";   // ваш коннектор

runFootballOrHockeySync({
  label: "mybook",
  bookmakerSlug: "mybook",
  sportSlug: "football",
  sportName: "Футбол",
  fetchMatches: () => fetchMyBookMatches(),
});
```

`runFootballOrHockeySync` сам создаёт конторы и матчи в базе, склеивает карточки, проверяет кэфы на правдоподобие
(`lib/consensusCheck.ts`, `lib/oddsSanity.ts`) и пишет снимки цен.

## 3. Регистрация конторы в интерфейсе

1. `lib/syncRunner.ts`: добавьте slug и отображаемое имя в таблицу названий.
2. `lib/prematchBooks.ts` и `lib/bookmakerOrder.ts`: порядок и подписи колонок на доске.
3. `sync-config.json`: включите контору в блоке `bookmakers` (то же можно сделать на странице «Статус»).
4. Запуск по расписанию: `sync-scheduler.sh` читает `sync-config.json` и запускает `sync-<slug>.ts` каждой включённой конторы.

## 4. Live (необязательно)

Live-трекер опрашивает конторы по очереди. Для каждой нужна функция, возвращающая `LiveOdds | null`
(см. заглушки `lib/collectors/book*Live.ts`):

```ts
export async function fetchMyBookLiveOdds(externalId: string): Promise<LiveOdds | null> {
  // null = матч у конторы сейчас не идёт; иначе price1/priceX/price2, счёт и минуту, если контора их отдаёт
}
```

Добавьте slug в `LIVE_ADAPTER_SLUGS` и `LIVE_ADAPTER_DISPLAY` (`lib/liveAdapters.ts`) и подключите вызов в `live-tracker-poll.ts`.
Одна конторa должна быть «якорной» (`MANDATORY_LIVE_ADAPTER`): по её live-ленте определяются начало и конец матча.

## 5. Проверка

```bash
npx tsc --noEmit
npx tsx sync-mybook.ts      # один прогон: должны появиться матчи и снимки цен
npm run dev                 # доска: колонка вашей конторы с кэфами
```

Если матч не склеивается с остальными: проверьте формат `leagueName` и время `kickoffAt`, затем запустите
`npx tsx ai-dedup.ts` (нужен ИИ-шлюз, см. `.env.example`) или поправьте правила в `lib/matching.ts`.

## 6. Что не стоит делать

- Не храните логины, токены и адреса прокси в коде: только в `.env`.
- Не публикуйте свои коннекторы в публичный репозиторий, если они содержат закрытые адреса, ключи или обходы защиты.
- Не показывайте устаревшие цены как текущие: если данных нет, отдавайте `null`, интерфейс покажет прочерк.
